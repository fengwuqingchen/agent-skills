# 续跑与恢复协议

## 持久状态

用一个任务专用目录，状态至少包括：

- task_id、project_path、plan_path、skill_path（均使用绝对路径）。
- timezone、protected_intervals（明确开始/结束日期）、background_cutoff、authorization_end。
- recurring_usage_pattern（用户原文、适用日期范围与时区，仅用于展开本次protected_intervals）；next_personal_interval；仅保护实际使用区间，不提前停工或预留周额度。
- phase：RUNNING / WAIT_QUOTA / RESERVED / BLOCKED / DONE。
- acceptance：每项 requirement、status、evidence；unknown 和未执行不能记 pass。
- progress：已完成、未完成、next_action、next_command、changed_files、active_processes。
- limits：checked_at、limit_id、短/周已用百分比、真实 reset、是否允许普通使用；无读数写 null。
- budget：周预留0、允许自动刷新跨周、reset_credit_authorized及卡使用记录、运行消耗观察。
- automation：id、完整可审阅 prompt、timezone、planned_runs（本批展开的带日期时区时间点）、next_run、verified_at、authorization_end；保存对用户告知的时间及通知条件。
- last_exit_reason、updated_at；若 DONE，再写 completed_at 和最终验收文档。

不把环境变量、cookie、token、密码或完整账户响应写进状态。恢复时先核对源码/Git/进程再执行 next_command，命令记录不是盲执行脚本。

## 创建时就验证续跑链

1. 发现 automation_update，读取已有自动化列表（按工具要求检查 automations/*/automation.toml 的名称/提示词）避免重复；不能覆盖别的任务。
2. 默认当前聊天 heartbeat。排程只包含保护区外、授权截止前的恢复机会。优先下一真实额度 reset+2min；如需故障恢复机会，也列为有限、具体的时间点，不默认额外创建周期 watchdog。不是固定只允许两轮，也不是无限次数：以实际使用区间和用户明确截止约束。
3. 若短窗口早已满且 reset 未到，不频繁唤醒模型检查。同样，周额度满时不要每5h重试；若周reset超过用户明确截止则停止排程；截止前允许下一周自动刷新后的额度。
4. 优先使用带日期、时区的固定且有限时间点；先计算并保存展开后的每个触发时刻，再提交调度工具。避免以 every/滚动间隔作为对用户的日程说明。只有固定点确实无法表达时才用有限规则编码，仍须向用户列出展开后的全部时刻、解释限制，不假装规则本身就是固定点保证。调度工具对分钟区间、绝对日期、时区的实际支持须现场核实。可用多个有限时间点/时段覆盖目标，但每项同属本任务且共享 checkpoint，任意时刻只有一个执行者。不要用全天每30min规则后才在提示词里退出：保护时段的模型唤醒本身也耗额度。
5. 复核返回与可读配置中的 next_run/timezone/截止（工具未返回时诚实标未知），不能只核对 BYHOUR 而忽略日期或UTC。不得手改 TOML。既有 COUNT/日期已经过期必须更新，不能等“自然再来一轮”。
6. 用户要求“先全部清空再重排”时是例外：按 target_thread_id 删除本聊天已有日程后再创建，不触碰其他聊天；一般 reset 或保护计划变更时，用工具更新现有任务并保存返回。heartbeat 被触发时先确保下一次故障恢复机会还有效，然后开始工作。达到 DONE 时暂停任务及其 watchdog；不得为输出已完成制造长期空转。

用户允许的夜间必须纳入排程。使用带明确日期/时区的开始时间或UTC时间集（以工具实际支持为准），验证有限排程跨午夜的结果；不能为了避开时区问题长期只安排双方时区恰好都安全的白天小时，导致00:00后整夜闲置。无法可靠表达时区时记录具体调度缺口，继续当前已允许工作，不声称夜间续跑已获保证。当前轮仍在执行时不得重复启动；恢复后按最新真实额度重新排下一次机会，不沿用过期reset。

guard支持`protected_intervals=[{start,end},...]`；旧单次`protected_start/protected_end`仍兼容。每段带UTC偏移，跨午夜的end写次日日期。合并重叠实际使用区间，周预留恒为0；授权截止不因weekly_resets_at提前，允许跨周自动刷新额度。旧personal_reservation_enabled=false只表示不留额度，不可清空实际使用区间。

## Heartbeat 提示词模板

替换花括号为真实值。写成用户可阅读的连续说明；保留完整任务终点，不只写“继续之前工作”。

> 使用 {skill绝对路径} 继续本聊天已授权的 plan {plan绝对路径}，项目 {project绝对路径}，任务 ID {id}。先读 {state.json}、{checkpoint.md}，核对 Git、进程、实际代码和验收证据，从中断点继续，不重做已完成或已提交的外部动作。先检查本次真实额度、用户保护时段 {带日期时区区间}、后台停止边界 {时间}、周预留0、跨周刷新及已授权重置卡策略 和授权截止 {时间}。有额度且有可执行工作必须继续实现和必要验收，不得只汇报、只规划或无理由结束；额度拒绝则按实际 reset 恢复，保护区内不运行。任务完成的标准是 {具体验收条件}。若状态已 DONE 且无新增任务，仅输出“已完成”并确保本任务自动化停用。每个可恢复增量落盘，长操作前保存检查点；任务未完成不得声称完成。权限和外部依赖真正阻塞时先找安全替代，仍不可解则说明唯一待用户动作。无变化/额度未恢复保持安静，只在完成、真实阻塞、需要用户操作时通知。按SKILL的条件使用已授权重置卡，未授权不得消费；不购买额度、改变账户/模型或重建任务绕过限制；不超明确授权截止，不创建新聊天。

## 三个用户 case 的具体决策

1. **触及 5h 限额、未完成**：触限前已有 durable checkpoint 和已验证恢复计划；下次真实 reset 后在允许窗口继续。5h 是计费窗口，不是要求模型连续运行五小时，也不意味已经运行五小时才会耗尽。
2. **未触限、已完成**：立即交付并停自动化；若在途续跑仍到达只输出“已完成”。不无意义消耗剩余额度。
3. **19:00–次日00:00使用电脑**：仅19:00至次日00:00停工，之前可持续工作，不预留周额度。近耗尽先按授权核实重置卡；无卡则在自然reset+2分钟且使用区间之外恢复。其他共享会话也会消耗额度，skill只能管自己的任务。

“未触限、未完成，却无理由主动结束”属于执行缺陷。每次恢复若发现上次是这种退出，应记录它，并立即继续，而不是把正常回合结束当成计划完成。预算保护、用户取消、真实权限/外部故障是可审计例外，不能伪造或隐藏。

## 依据与限制

官方来源核对于2026-10-25；后续实际工具/账户读数优先，不假设文档永远不变。

- [官方额度说明](https://learn.chatgpt.com/docs/pricing)：模型、上下文、推理、工具与缓存影响消耗；额度共享，重置/剩余应看账户。本skill不按经验百分比预留周额度。
- [官方定时任务](https://learn.chatgpt.com/docs/automations?surface=app)：当前聊天可安排恢复、任务可调用 skill；本机项目要求机器开机、应用运行。后台任务受当前 sandbox 与服务可用性约束。
- Skills 是行为指导，非额度预留 API、常驻执行器或硬中断控制器。平台拒绝后的最后写入可能无法发生，所以必须增量落盘并预设续跑。排程成功不等于未来触发已经验证。

## 只读 guard 输入示例

将真实账户工具读数映射到这些字段后运行 `python3 scripts/quota_guard.py /absolute/private/guard-input.json`。时间必须带偏移；不给普通使用许可/额度数据时返回 UNKNOWN，不能猜测账户有额度。authorization_end 使用用户明确截止；未指定可省略，不能由周reset缩短，不能默认为使用时段开始。使用时段结束后仍需刷新真实读数，才继续。

```json
{
  "now": "2026-10-26T08:00:00+08:00",
  "protected_start": "2026-10-26T19:00:00+08:00",
  "protected_end": "2026-10-27T00:00:00+08:00",
  "authorization_end": "2026-10-28T08:00:00+08:00",
  "short_window_minutes": 300,
  "ordinary_usage_allowed": true,
  "short_used_percent": 40,
  "weekly_used_percent": 10,
  "short_resets_at": "2026-10-26T11:00:00+08:00",
  "weekly_resets_at": "2026-10-28T08:00:00+08:00",
  "next_operation_weekly_percent": 2
}
```


## 用户要求验证真实唤醒时

允许在原聊天为真实调度验收增设一个固定、单次节点，与主续跑共享checkpoint及预算。明确告知验收时间和目的；先保存检查点、结束人工轮，让调度器有机会在空闲聊天实际派发，不能一边保持本轮执行、一边将“未重复启动”当作漏唤醒。该验收接手时核对本次created_at之后的last_run/运行证据，暂停验收日程，然后继续原任务；不能暂停主日程或无限创建探针。尚未实际触发前，只能说排程已验证，不能说真实唤醒已验收。该有界交接是验证外部调度所需的步骤，不是阶段完成后无理由停止项目。
