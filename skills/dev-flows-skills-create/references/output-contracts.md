# 输出与交接契约

写每份生成 skill 时确定下列职责接口。它们是生成设计要求，不强制使用固定标题或统一 YAML schema。

## 独立调用

每份 skill 说明：适用请求和范围输入；需要读的实际权威与定向参考；允许动作；可交付结果；证据不足处理；普通完成与阻塞停止条件。可以从用户已有请求推断低风险输入，不因缺一个形式字段开始完整访谈。

| 职责 | 输入重点 | 有效结果 | 普通停止点 |
|---|---|---|---|
| find-simplifications | 调查/实施范围、保留义务、消费者 | 有证据候选、净收益和取舍、拒绝/延期；授权实施才有代码变化 | 请求范围足以支持结论，没有继续扩范围凑数量 |
| pre-push-checks | 当前差异/交付版本、运行环境、已有证据 | 变化到检查的映射、实际结果、缺口；授权 push 才发布 | 相关证据足够，或明确失败/环境阻塞；CI pending 不冒充通过 |
| prose-standard | 目标文字、读者、审核或编辑权限 | 命题完整的改写或审核发现，必要保留和延期 | 请求范围已覆盖，无命题损失；不继续清理无关文件 |
| human-doc | 读者任务、事实源、文档范围 | 可用的指南/参考/规范或结构建议，验证状态 | 读者可沿入口识别成功与处理常见失败，事实归属明确 |
| code-review | 对象、基线、用户意图、审核/修复范围 | 可复核发现或无发现结论，位置、影响、证据与局限 | 相关高价值行为路径已覆盖，结论达到证据限度 |

阻塞只针对依赖缺失的动作，独立工作继续。例如缺发布凭据不妨碍本地 skill 完成；缺明确基线可以审核现状但不能声称缺陷由某个 PR 引入。不要因不确定而循环读取更多无关材料。

## 辅助读取不等于递归执行

在交叉链接旁说明读取理由和范围。读 prose-standard 的命题规则，不意味着执行一次文字审计；读 pre-push-checks 的证据映射，不意味着 commit 或 push。

文档与文本规则可以相互引用，但不能互相无条件启动完整工作流；普通完成后返回原请求。没有为 agent 工具实现运行路由时，所有关系都只称为指导加载关系。

子集生成时不能留下对未生成 sibling skill 的悬空引用。需要相同原则时链接项目已有规范，或在当前入口保留最小必要规则，不扩大生成范围。既有同职责 skill 可作为实际引用，先确认其契约适配。

## 生成顺序与共享约定

先确定项目身份、输出位置、文档权威和验证入口。对共享规则只确定一个归属。

正文标准、文档组织与证据选择会被其他职责使用，先确定其实际接口，再生成调用它们的简化和审核指导。独立部分可以并行草拟；集成前以实际文件核对链接、名称、触发、允许动作和停止点，不使用仍在想象中的接口。

五份不必采用固定生成次序；依赖已写契约的内容必须等待它明确。已有项目规范也可以替代共享 skill，避免为了“顺序完整”重建规则。

新政策、模板和检查须标记本次建立的状态。已经生成脚本不代表接入 CI，已经生成指令不代表目标运行器发现了它。交付明确落地到哪一层，未授权部分只给接入点。
