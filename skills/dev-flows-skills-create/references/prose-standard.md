# 生成 prose-standard

用于判断写、补、改、删哪些文字，覆盖项目适用的文档、注释、提示词与可见字符串。它是编辑标准，不是机械压缩器。审核和写入权限来自用户任务，不能由模式选项扩大。

## 完整命题

保留行动者与动作、条件、时点和顺序、义务强度、否定、例外、所有权、副作用、失败、后果及数量边界。文字更短不证明更好；文字少到无法安全使用时需要补充。

区分局部必要事实与非局部解释。调用者需要的行为契约可局部保留，架构和理由尽量引用所属文档。术语用于准确指称，不用统一禁词表删除有意义机制名称。

## 按项目选择文本位置

- 公开接口：返回区别、异常、时序、取消、资源与持久性。
- 内部/模块注释：非显然结构、不变量、竞争、安全和维护陷阱；不复述代码流程。
- 测试：只解释非显然 fixture、入口、观察方式及平台适配，不写测试执行过程讲解。
- 教程：前提、真实入口、动作、成功信号和失败恢复。
- README/参考：消费者配置、语义、失败、限制和扩展点；链接生成 API，不手写重复目录。
- 决策：独特理由、真实备选方案、后果、证据和缺口；已落地正文不能继续作为待执行计划。
- 故障复盘：经过、证据、因果、影响和预防；不能因为出现历史语气就删掉。
- skill/指令：触发条件、约束、范围、加载规则；引用具体责任方。
- 提示词/UI/CLI：措辞可能改变行为，沿实际消费者与本地化机制验证，不并入纯文字清理。
- 诊断：失败对象、规则及必要修复线索，不泄露敏感信息或无用内部过程。

只输出项目真实存在的位置规则；例如没有模型输入就不规定模型快照，没有多语言机制就不虚构字典要求。

## 编辑与清理流程

尊重范围；缺少必要范围时只询问关键缺口，不自动全仓库清理。识别生成与冻结文件，按其所属规则处理，不按目录名字推定。生成源先改，派生输出再生成；正文更新不自动授权行为变化。

无效草稿编号、不可解析会话引用、评审辩解和代码复述可删除；含真实事实的段落先保留命题再去过程叙述。有效 issue 引用、必要忽略理由、现在时反事实和复盘证据不是一概禁止。

已有同义术语和例外遵循项目规范。明确编辑可直接应用，真实原则冲突用可行替代方案说明差别；没有用户要求不用为每句启动互动校准。输出报告范围、修改、必要保留、延期和实际检查，不能以删字数当成果。
