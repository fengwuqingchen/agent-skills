# 项目发现与适配维度

生成前使用本文件定位会改变指导的项目事实。无需把本表复制到每份输出，也不必逐行检查无关领域。

## 最小证据集

先定位项目根、适用 `AGENTS.md` 或等效指令、已有 skills、工作树状态、构建/测试入口、CI 与发布说明，以及当前文档入口。优先 `rg --files` 和定向读取，排除依赖、缓存、生成目录及无关历史；不为了建规范遍历所有源码。

有 Git 时只读当前工作树与用户指定基线；不要擅自切换分支、拉取未知远端或改写历史。确认现有 dirty 文件后只改生成范围。非 Git 项目也可生成适用指导，其检查 skill 说明实际交付/同步流程，不能假设存在 PR 或 push。

命令来源优先仓库实际 task runner、manifest、Makefile、测试配置和 CI，随后确认其入口及参数。文档和脚本不一致时沿脚本/配置与当前代码核对，不自动执行安装、生产操作或 secret 相关命令来“确认”。

临时保留事实记录：主题、观察到的证据位置、验证状态、对哪份 skill 有影响。它是创作工作集，不必成为额外交付文档；只有多份输出确需共享长期规则且无现有归属时才建立公共规则文件。

每个领域找到足以影响输出的当前机制和证据入口即可停止发现；仅继续查会改变核心指导的冲突或缺口。现有文档、实际脚本和 CI 不一致时记录差别与当前可复现入口，不能默默挑最方便的一份作为权威。缺少决定性事实时缩小结论或明确条件，不必把整个代码库都读完。

## 选择值得深入的维度

| 维度 | 要查的区别 | 对生成内容的影响 |
|---|---|---|
| 项目身份与范围 | 库、产品、服务、CLI、插件、研究仓库；单仓或多仓 | 读者、对外契约、skill 前缀与归属位置 |
| 架构与组合 | 单体、组件、服务、动态加载、代码生成、扩展机制 | 消费者调查、真实入口、局部与跨组件检查 |
| 对外使用 | 终端用户、内部团队、第三方开发者；承诺支持的入口 | 文档类型、公开 API、破坏性变更与审核关注 |
| 数据与兼容性 | 数据库、文件格式、队列、协议、旧客户端、滚动升级 | 迁移、回放、历史 schema、可逆性与验证证据 |
| 状态与资源 | 生命周期、并发、异步工作、外部进程、重试、取消 | 所有权、完成/失败通道、清理和恢复的审核原则 |
| 执行与平台 | 本地、云、容器、多平台、离线、产物安装 | 前提、环境限制、源入口与发布入口证据 |
| 身份与安全 | 租户、授权、secret、输入信任、个人数据 | 真实执行点、跨边界校验、示例脱敏和权限范围 |
| 发布与运维 | 持续部署、版本发布、组件独立发布、回滚 | 迁移指南归属、检查时点、生产操作停止条件 |
| 工作流与团队 | 人/agent 分工、review、branch、hooks、CI、外部工具 | 验证选择、授权、加载机制、避免重复检查 |
| 文档权威 | 现有教程、参考、ADR、任务/plan、生成参考 | 事实归属、更新而非重复创建、生命周期适配 |
| 本地化与发布 | 单语或双语、术语、翻译责任、网站投影 | 按需配对、质量审核、生成源与公开映射 |
| 产品体验 | CLI/UI/模型可见文本、无障碍、交互反馈 | 文本视为行为、适当场景与快照证据 |
| 性能与依赖 | 延迟、内存、体积、流量、成本、第三方能力 | 简化净收益、真实负载与依赖替代边界 |
| 可验证性 | 测试层、密钥限制、样例、构建 smoke、已有校验 | 可执行命令、证据缺口、人工确认责任 |

沿代码/配置寻找实际消费者与生产者；“没有搜索结果”并非一定无用，外部用户、动态加载、序列化键或安装产物可能仍依赖它。对关键信息不足的项目生成有条件的调查指导，不编造架构、版本承诺和自动化能力。

## 事实与选择的分离

- 已存在且有依据的规则：引用所属文件，不另写第二套。
- 用户明确要求：纳入输出，冲突时按授权解决并说明影响，不将其伪装为已有事实。
- 合理建议：写明可选择及适用条件，避免未经授权变成强制制度。
- 未确认事项：注明需核对的所属文件或责任方；风险相关决定不能用沉默当作批准。

用户明确要求“建立规范”时，区分能在当前范围实施的新规则与需要额外动作的接入。可以创作决策格式、文档模板和相关检查，但先解释它们解决的项目问题，并在实际生成后才称为存在；不能因为原项目缺少制度就永远只引用旧 README。没有授权重组旧文件时，新规则说明兼容过渡，不擅自批量迁移历史。

无需默认复制 `proposed/implemented/rejected/archived`、`.i18n.yaml`、冻结 manifest、Cordis、100% 覆盖率、特定包管理器、PR stack 或本地化框架。这些只有存在实际用途、项目约定或用户明确要求时才生成。
