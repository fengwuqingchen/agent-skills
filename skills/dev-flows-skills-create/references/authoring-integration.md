# 输出结构、加载与接入

## 文件归属

用户指定位置优先；没有指定时先沿用项目已存在的 skill 根。目标运行器支持仓库级 `.agents/skills/` 且没有更具体约定时，可采用该位置；否则使用运行器确认支持的目录或指定交付目录。全局安装只有用户要求或明确需要时进行，不能把项目专属规则污染无关项目。

已有同职责 skill 时按任务更新或补充路由，不创建两个名字不同的同权威标准。五类默认是职责目标，不要求强行替换既有名字。用户明确要五份新 skill 时按其要求生成，仍标明现有权威引用。

更新前读取现有入口、调用政策与支持文件，查明它们的引用者；保留仍有效的用户例外和可选元数据。删除、合并或改名支持资源前修复所有消费者；只更新一个职责时不覆盖整组。旧职责不在新生成范围不等于获准删除它。

## 每份入口应表达什么

- `name` 与目录同名，description 说明哪类请求使用，避免“所有开发都用”。
- 必需 scope、事实来源和项目真实的不显然约束。
- 调查、审核、写入、提交和外部动作的区别；已有授权不重复索要。
- 思考角度和有效结果；并非每个角度都是强制检查表。
- 相关指令、支持文件的准确路径与何时读取。
- 真实验证入口，及不足证据如何报告。

每份还需要有效结果和停止条件，见入口链接的输出与交接契约。description、入口与 references 的动作权限必须一致；不能 description 写“审核”而正文默认改代码。

跨文件链接用可解析的相对路径；只链接实际存在或本次生成的文件。支持资源不能指回生成器的私人路径。若需要共享规则，优先链接项目现有所属文件；没有且确需共用时，在授权范围建立一个所属文件并从五份入口链接。

## 职责间的关系

- 简化调查形成实质提案时，遵循项目决策规范；修改文字时才使用文本标准，不自动展开全库文字审计。
- 文本标准管理命题完整性；human-doc 管理文档归属与读者结构；避免重复完整规则。
- code-review 对照前两者审核新文字与文档，但不自动实施修复。
- pre-push-checks 选择证据；其他 skill 可指出需要哪类证据，不能各自规定互相冲突的全套检查。
- 决策归档、升级指南、翻译等额外职责优先引用项目已有规则。默认五份之外不自动新增额外 skill；只有有持续独立用途且属于请求范围才增加。

`AGENTS.md` 的继承与自动加载属于运行器行为，应核对环境支持；在文件里写“必须加载”是指导，不能当作已实现的自动加载代码。可提供请求到 skill 的映射，不声称存在路由器。

## 支持资源何时值得创建

长且条件性的指导放 `references/`，入口直接链接并注明读取条件。只有一种短流程不需要空 router。真实格式有重复创作需求时才建模板；项目已拥有模板则引用，不复制。

不要把关键硬约束只留在无条件无法读到的参考。根据触发范围决定载入哪些文件，用短定位说明实际目录与名称；名称叫 `references/` 本身不能保证运行器自动加载。公共规则和项目私有约束可不同深度，但都需要当前入口能找到。

机械验证或重复转换值得脚本时才写 `scripts/`；新脚本必须运行，并能用正反例证明其要检查的行为。没有授权接入 CI 时保持脚本可单独运行并报告接入未完成。不要为了让文档看起来可执行而造并未运行的命令。

标准 skill 使用 `SKILL.md` YAML `name` 与 `description`。目标支持且需要 UI 元数据时才生成 `agents/openai.yaml`，遵循该环境格式；不默认修改显式/自动调用政策。引用 skill-creator 仅当目标环境可用，不能生成悬空依赖。

## 内容深度与排除

中文或用户指定语言正文即可，不强制双语。生成结果中每条“必须”应能追溯到用户要求、项目事实或该工作流的真实正确性/权限边界；可选择的约定写成建议或条件。

不新增 README、安装手册、changelog、事实清单副本或复杂目录来凑完整性。不自动迁移已有 docs/notes，重写历史记录、封存或删除需要相应任务范围。不同领域适配可以增加思考角度，但删除无实际机制的要求比保留空章节更好。

不将密钥、账户信息、个人绝对路径、内部地址或未经要求的历史示例带入可分享产物。引用项目路径可以是实际仓库相对路径；公共生成器的示例采用明确虚构项目，不携带目标项目私有信息。
