# 生成 pre-push-checks

用于项目真实提交/交付前选择和运行相关证据，不能默认 full suite，也不能只检查 Markdown。没有 Git 的项目明确适用的是交付验证，不编造推送步骤。

## 生成实际证据映射

从 task runner、测试配置、CI 和发布产物确定以下适用关系；输出写真实命令、入口、前提和范围参数，不写通用占位命令。

| 变化面 | 需要考虑的证据 |
|---|---|
| 局部逻辑 | 所属测试，以及共享契约影响的消费者 |
| 接口/类型 | 编译或类型检查、消费者和生成定义 |
| 文档/决策/skill | 实际文档校验器；不存在时检查本地链接与事实并准确报告 |
| UI/CLI/模型可见内容 | 所属行为场景、可访问性、快照或 runnable example |
| 配置/动态组合 | 真实配置入口，而不只是手工构造单元 |
| 打包/export/安装入口 | 构建与安装后产物 smoke，不能用源码测试代替 |
| 数据/协议/迁移 | 兼容、恢复、旧数据与失败路径 |
| 异步/资源/平台 | 真实并发、恢复、取消、清理和平台限制 |
| 外部提供者 | 有授权和凭据时的真实验证；没有时报告证据缺口 |

区分“必须达到的行为证据”与某个命令建议。已有 hooks 和 CI 做什么应准确描述；不用臆造增量 hook、逐文件覆盖率或快照目录。变更基线由当前项目流程确定；无 PR 时不要求查询 PR。变更范围包含本次未提交修改，不能只看上次提交。

## 失败、历史和执行边界

已通过证据不用因 commit/push 再次重复；后续修改或合并使其失效才重跑。全套检查只在用户要求、诊断或确实无法缩窄的变化时建议。

测试文件筛选、测试名筛选与覆盖率范围是不同概念，确认 runner 的实际转发语法及选中数量。不能用允许无测试、缩小范围或放宽阈值掩盖失败。

普通发布前相关检查失败，修复或报告阻塞，不能期待 CI 自动不同。环境归因需精确失败信息与相关证据；不能自动绕过 hook。远端 pending/未运行不能称为通过。

推送、历史改写和发布需要任务授权。若项目允许历史改写，要求保护并发远端修改，不能无条件 force。若工具把重写与发布合在一起，明确先后限制、发布后验证及禁止合并条件；仅项目确实使用该工具时描述。

不把验证调用转成安装全局依赖、运行生产迁移或付费真实请求。缺环境时保留可运行指导并报告未验证项。执行报告只列实际运行和结果，区分未运行、通过、失败、pending。
